# T-0011 — Flat-Table Baseline Agent Implementation

Backlog ref: `BL-012` · Sprint: `Sprint 4` · Priority: `Must`

## Intent
Implement the legacy flat-table baseline agent in `packages/eval/src/baseline.js`. The baseline simulates traditional tabular rules (per-account feature vectors with naive velocity and shared-IP thresholds, without multi-hop graph traversal or Skeptic challenges) to serve as the comparative benchmark against SENGRA's graph agent.

## Scope / Out of scope
- **In Scope**:
  - `packages/eval/src/baseline.js`: `evaluateBaseline(accountRow, relatedRows)` implementing tabular heuristic rules.
  - Failure mode 1 (False Negative on Ring A): Misses mule ring accounts separated by $\ge 2$ hops from flagged devices.
  - Failure mode 2 (False Positive on Ring B): Incorrectly freezes legitimate family members sharing residential IP/address due to missing Skeptic challenge.
  - Unit tests verifying baseline behavior and reproducing benchmark failure modes.
- **Out of Scope**:
  - Side-by-side UI comparison page (handled in T-0012).

## Requirements
- `REQ-001`: Comparison baseline demonstrating superiority of graph-native investigation.
- `REQ-005`: Policy benchmark testing false-positive and false-negative rates.

## Acceptance
- `AC-012-a`: `evaluateBaseline()` evaluates account using tabular attributes (transaction count, velocity, direct device link).
- `AC-012-b`: Baseline produces false positive on Ring B (returns `FREEZE` for benign family members sharing home network).
- `AC-012-c`: Baseline produces false negative on Ring A (returns `NO_ACTION` for collector mule 2 hops away from D-17).
