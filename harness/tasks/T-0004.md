# T-0004 — Graphology In-Process Analysis & Pure Policy Engine

Backlog ref: `BL-004`, `BL-005` · Sprint: `Sprint 1` · Priority: `Must`

## Intent
Implement in-process graph analytics in `@sengra/analysis` (Louvain community detection, betweenness centrality, connected components, graph density, and cross-check verification) and pure deterministic risk policy in `@sengra/policy` (`evaluateFreezePolicy`, `skepticCheck`, `DECISION_ACTIONS`).

## Scope / Out of scope
- **In Scope**:
  - `packages/analysis/src/index.js`: `analyzeSubgraph(nodes, edges)`, `computeCentrality(nodes, edges)`, `crossCheckComponents(falkorWCC, graphologyWCC)`.
  - `packages/policy/src/index.js`: `evaluateFreezePolicy(input)`, `skepticCheck(input)`, `DECISION_ACTIONS`.
  - Unit tests verifying Louvain community clustering, betweenness centrality bridge identification, freeze policy logic (FREEZE, HOLD, NO_ACTION), and skeptic benign cluster clearance.
- **Out of Scope**:
  - Direct HTTP route handling or MCP client transport (covered in Sprint 2).

## Requirements
- `REQ-003`: In-process Graphology analysis (Louvain, betweenness, WCC cross-check).
- `REQ-005`: Pure deterministic graph-gated policy engine.
- `REQ-008`: Skeptic challenge rule engine verifying benign explanations.

## Acceptance
- `AC-003-a`: Given nodes and edges of a suspect cluster, `analyzeSubgraph` computes Louvain community IDs, betweenness centrality, and component counts.
- `AC-003-b`: Discrepancies between FalkorDB WCC and Graphology components downgrade confidence and route to HOLD.
- `AC-005-a`: Account in ring with >= 3 flagged accounts, within 2 hops of known bad device, without prior clearance returns `FREEZE`.
- `AC-005-b`: Partial evidence returns `HOLD`.
- `AC-008-a`: Family cluster sharing address and IP with no bad devices clears via `skepticCheck` and returns `NO_ACTION`.
