# T-0002 — FalkorDB Client & Zod Entity Schemas

Backlog ref: `BL-001` · Sprint: `Sprint 1` · Priority: `Must`

## Intent
Implement `@sengra/schema` containing Zod schemas for all domain entities, relationships, and tool inputs/outputs, and `@sengra/graph` implementing the FalkorDB connection client with singleton caching on `globalThis`, TLS configuration, environment prefixing, and parameterized query execution (`query` and `roQuery`).

## Scope / Out of scope
- **In Scope**:
  - `packages/schema/src/index.js`: Zod schemas for Customer, Account, Device, IPAddress, Card, Address, Transaction, Merchant, Rule, relationships, and subgraph models.
  - `packages/graph/src/index.js`: FalkorDB connection singleton caching (`globalThis._falkor`), TLS socket configuration, prefix-aware graph selectors (`domain`, `agentMemory`, `decisions`), and query runners with parameterized execution.
  - Unit tests verifying schema parsing and client helper behavior.
- **Out of Scope**:
  - Graph algorithms or MCP endpoints (covered in T-0004 and T-0005).

## Requirements
- `REQ-001`: Multi-hop entity expansion models.
- `REQ-002`: Graph algorithms parameter validation.

## Acceptance
- `AC-002-schema`: Zod schemas validate node attributes (`known_bad`, `flagged`, `frozen`) and edge properties.
- `AC-002-client`: `getDb` caches connection on `globalThis`; graph selectors honor `FALKORDB_GRAPH_PREFIX`.
- `AC-002-ro`: Read-only queries use `roQuery` to ensure database-level write rejection.
- `AC-002-unit`: Hermetic unit tests in Vitest verify schema validation and client configuration.
